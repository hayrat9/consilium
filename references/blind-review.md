# Анонимная проверка аргументов в R2

Не заменяет источники, предметный спор и R3. Применяется в review и brainstorm,
в full и light. В R1 генерации идей нет баллов; первичная оценка начинается в R2.

## До передачи оценщикам

Ведущий фиксирует критерии и единицы оценки: ответы R1 либо отдельные идеи/аргументы.
Сохраняет исходные тексты и происхождение. Для новых комбинаций сохранить parent_ids
в ideas.json; в authors перечислить объединение авторов всех родителей и соавторов.
Тогда ни один соавтор не оценивает совместный ответ. В полной сессии один критерий
может быть неприменим к конкретной области — это отметить, а не подставлять ноль.

Убрать из оценочного текста имя роли/модели, самопредставление и подпись. Для каждой
такой правки сохранить связь с исходником и перечень изменений; нельзя переписать
аргумент для улучшения оценки. Ссылки E-ID, проверяемые факты и ограничения оставить.
Содержание и стиль могут выдавать автора: это маскирование метаданных, не гарантия
невозможности угадать. Имя автора цитируемой работы не равно автору ответа.

Формат входа для scripts/blind_review.py:

```json
{
  "criteria": [{"id": "evidence", "question": "Чем подтверждён основной тезис?"}],
  "reviewers": ["R1", "R2", "R3"],
  "submissions": [
    {"id": "S1", "authors": ["R1"], "content": "Аргумент без подписи", "source_ids": ["E1"]},
    {"id": "S2", "authors": ["R2"], "content": "Другой аргумент", "source_ids": []}
  ]
}
```

```text
python scripts/blind_review.py prepare submissions.json --output-dir review-packets
```

Помощник исключает собственные/совместные ответы, отдельно перемешивает порядок,
даёт локальные псевдонимы A01… и сохраняет panel-001.json и следующие для оценщиков.
criteria и список кандидатов — весь prompt. Только нужный panel передаётся нужному
оценщику. mapping.json и manifest.json остаются у ведущего: в них есть соответствия
авторов/оценщиков. Не передавать их, исходную сессию, досье или чужие панели в контекст
независимой оценки. Seed необязателен и служит воспроизводимости, не криптозащите.
Не генерировать пакеты повторно после начала оценивания: продолжать сохранённые.
Новые существенные материалы требуют новой версии пакетов и отдельного журнала.

Использовать свежие разрешённые контексты оценщиков, которые не видели R1 авторов.
Если делегирование отсутствует или исполнитель уже видел ответы, выполнить доступную
маскированную проверку и явно записать `blinding: metadata_only`. Не утверждать слепоту
или независимость в том же контексте. При полном отделении — `fresh_contexts`, всё
равно без обещания защиты от стилевых подсказок. Смена модели не заменяет маскирование.

## Оценка и возвращение происхождения

Оценщик по каждому кандидату даёт alias, verdict (support/amend/challenge/unclear)
и содержательный reason с критериями, источниками, ошибками и проверяемым возражением.
Оценки не являются голосованием за истину. Для численных оценок использовать отдельно
уже согласованные критерии/веса; этот помощник не подсчитывает популярность.

```json
[{"reviewer_id": "R2", "assessments": [
  {"alias": "A01", "verdict": "amend", "reason": "Тезис требует проверки по E1; предложен тест."}
]}]
```

```text
python scripts/blind_review.py join review-packets/mapping.json reviews.json --output review-results.json
```

Join проверяет соответствия и полноту, возвращает ID/происхождение и недостающие
оценки; частичный ввод допустим только с --allow-partial и получает status in_progress.
Не выдавать его за законченный R2. Если кандидатов нет (одна роль или все соавторы),
назначение явно skipped_no_eligible; самопроверка по критериям допустима, но не равна
взаимной оценке. Считать R2 завершённым можно лишь после карточек всех его ролей;
полный join не заменяет их. В обычной карточке R2 ссылаться на submission_id и разбирать
содержательное возражение; после закрытия оценок можно открыть авторство и обсудить
профильные ограничения. Итоговая таблица хранит исходную оценку и последующие поправки.

Карта авторов — рабочий файл, не надёжное хранилище секретов. Сохранять с обычными
проектными правилами доступа, без токенов/личных данных. Помощник работает офлайн,
не выполняет AI-запросы, не проверяет истинность и не гарантирует анонимность текста.
