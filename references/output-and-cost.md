# Представление, журнал, ресурсы

В начале вместе с составом предложить2–3подходящих формата,рекомендуемый и свой:
текст/таблица;полный отчёт;карта аргументов;графики;интерактивная модель;презентация;
видео/анимация/3D. Не делать всё автоматически. Уточнить отдельно результат и журнал:
только итог/ключевые узлы спора/карточки раундов/визуальная хронология.

Карта аргументов показывает поддержку/возражение,не доказанную причинность.
Графики требуют данных или явно подписанного сценария. Визуализация/видео берут
одно проверенное содержательное ядро result.json,не добавляют новые обещания.
Журнал — реальные внешние аргументы и изменения,не скрытые рассуждения модели.
Инсценировку явно подписывать,не выдавать за реальную запись публичных людей.

## Читаемый итог

Перед выдачей выполнить [редакторский проход](editorial-pass.md). Короткий итог должен
быть понятен самостоятельно, включая условия, способные изменить рекомендацию.
Подробные аргументы и выбранный журнал дать следующим уровнем, сохранив связи с
источниками. Объём соразмерять задаче; сокращать без потери доказательств и оговорок.

## Смета

Отделить подбор/исследование/совет от оформления. В оформление включить финальную
редактуру и сверку смысла; не обещать фиксированную экономию токенов или времени.
В full включить #last30; в light — выбранную адресную проверку фактов:
 план запросов, получение, чтение и проверку отраслевых
источников. Смету уточнять после проверки доступности; фиксированной надбавки в процентах
нет. Общий срез готовится один раз для ролей и форматов, повторная передача контекста
учитывается. Учебный пример ниже не является измерением расходов #last30.

Для того же состава показать
диапазоны суммарных текстовых токенов(контекст+ответы),активного времени до результата
и проценты относительно базового формата=100%. Основание:измеренная похожая сессия,
план по этапам или явно учебный сценарий. Без замеров не обещать точные проценты.

Роли,раунды,объём источников,исполнители/повторные чтения и медиа влияют по-разному.
Параллельность уменьшает время,но не суммарные токены. Ожидание пользователя
не включать в активное время. Очереди и рендер — отдельная неопределённость.
Токены не равны рублям:деньги считать только по известному актуальному тарифу и
объёму. Медиа могут тарифицироваться иначе. При неизвестности ставить«не оценено»,
не0рублей;не менять выбранную модель/провайдера.

estimate_resources.py получает интервалы анализа и добавок форматов. Проценты
рассчитываются при одной общей базе анализа,а не делением независимых крайних сумм.
Базовый формат сам к себе всегда100%. Время — сумма последовательных этапов;
параллельность уже должна быть учтена во входном времени анализа. При другой схеме
сначала оценить критический путь,а не применять заведомо неверную простую модель.

[Учебный вход](../assets/estimate.example.json):все числа вымышлены для проверки
арифметики,не норматив навыка. Для реальной сессии заменить сметой её этапов.
Пример можно показать только с маркировкой illustrative. Фактические счётчики
среды,если доступны,записывать отдельно;план не выдавать за«потрачено».

## Средства

Простая схема — Mermaid/текст;интерактивный инструмент — доступная визуализация/HTML.
Экспортируемый научный график — обычный plotting-инструмент с данными и единицами.
Перед специализированным вызовом читать реальные инструкции соответствующего навыка.

Видео и Blender использовать только при наличии подходящих инструментов и
зависимостей; этот пакет их не устанавливает. У ролика свой план сцен, длительность
и параметры рендера.
Сначала стабилизировать выводы,затем оформлять. Для новых слайдов тот же анализ
не выполнять повторно без новых причин.

Выбор медиа не разрешает новые платныеAPI,аккаунты,публикацию или раскрытие данных.
В итог включить вывод,основания,сильное возражение,неизвестное,следующую проверку и
по запросу карту/расчёт/хронологию. Завершить тремя конкретными направлениями углубления
и своим вопросом;не запускать их автоматически.


## Просмотр сохранённых раундов

```text
python scripts/render_rounds.py /path/to/session.json --output /path/to/rounds.html
```

Автономный HTML без сети: итог, таблица ролей с карточками R1/R2/R3 рядом, статусы,
история фаз и все поля карточек, включая поправки, источники и фактическую модель.
Показывает частичный раунд как частичный, не дорисовывает отсутствующие позиции.
Вычислять скрытое изменение мнения по стилю текста нельзя: изменения показываются
только в реально записанных карточках. Карточки исторического состава сохраняются.
Открыть файл в браузере; это просмотрщик отчёта, не сервер и не приложение вызова AI.
Не передавать его оценщикам до закрытия анонимного этапа. Для публичного размещения
отдельно проверить содержимое и права: файл отражает переданную сессию целиком по
карточкам, не является автоматическим обезличиванием. Рендер не повторяет исследование.
